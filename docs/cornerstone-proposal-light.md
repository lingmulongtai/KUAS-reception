## 1. このプロジェクトで何をするか

工学部のオープンキャンパスで使う **受付システム** を、学生チームが自分たちで開発・運用します。

現在の受付は、来場した高校生にその場で名前や学年を入力してもらい、リストと照合する方法をとっています。これに対して **QRコードを使ったスマートな受付** を実現し、受付ミスの削減・スタッフの負担軽減・来場者の体験向上を目指します。

---

## 2. 背景と課題

オープンキャンパスでは毎回、次のような問題が発生しています。

| 課題 | 影響 |
|------|------|
| 受付で名前を手入力 → 照合ミスが起きやすい | スタッフの対応に時間がかかる |
| 受付後、会場や担当教員の案内が口頭のみ | 来場者が情報を忘れる・迷う |
| 工学部生は全体受付と工学部受付の2回並ぶ必要がある | 混雑と時間のロス |
| 何度も来てくれているリピーターのデータがない | 来場者の傾向が把握できない |

---

## 3. 解決策・システム概要

```
【事前】大学からの参加者名簿（Excel）を取り込む
    ↓
全参加者に QRコード付きメールを自動送信
    ↓
【当日】来場者がiPadにQRをかざす → 即座に受付完了
    ↓
担当プログラム・会場・教員情報がメールで届く
    ↓
カラーリストバンドを受け取って体験へ
```

- QRが使えない場合は **名前・学年の入力** でも受付可能（代替手段あり）
- 全体受付ブースにiPadを設置することで、工学部生の **2回並び問題を解消**
- 来場者のリピート情報を蓄積し、入学センターへの**データ提供**にも活用

---

## 4. 主な機能

| 機能 | 説明 |
|------|------|
| **QRコード受付** | 事前送付のQRをかざすだけで受付完了 |
| **名前・学年入力（代替）** | QRがない場合でも問題なく対応 |
| **Excelインポート** | 大学からの名簿ファイルを取り込んで自動処理 |
| **プログラム希望の確認・変更** | 受付時に第1〜第3希望を確認・修正できる |
| **振り分けモード切り替え** | 先着順 or 全員受付後に一括振り分け（管理者が選択） |
| **受付完了メール** | 体験プログラムの場所・時間・担当教員を自動メール送信 |
| **来場履歴の蓄積** | リピーター情報を記録し、体験の優先度や分析に活用 |
| **管理者ダッシュボード** | リアルタイムで受付状況・空席数・待機者を確認 |

## 7. 予算・費用

### 予算（大学より支給・固定）

コーナーストーン制度により **5万円 × 5名 = 25万円** が大学から支給されます。
精算は**後払い・実費清算**で、実際に使った分のみが対象です。使い残した分の返還義務はありません。

### 費用概算（現時点・変動あり）

| 項目 | 年間概算費用 | 備考 |
|------|------------|------|
| Firebase（クラウドサービス費） | 0〜10,000円/年 | 従量課金。本規模ではほぼ無料〜数百円 |
| メール配信（Amazon SES） | 0〜500円/年 | 従量課金。年間ほぼ無料の見込み |
| 受付端末（iPad等） | 0円 | 大学・学部からの借用を想定 |
| 開発ツール・ライセンス | 〜10,000円 | デザインツール等 |
| **費用合計（概算）** | **〜20,500円** | |

> 予算25万円のうち、実際に費用として発生するのは現時点の概算で2万円程度の見込みです。差額は請求しません。

## 8. 個人情報・セキュリティについて

参加者（高校生）の氏名・メールアドレス等を扱うため、セキュリティ対策を徹底します。

- データはすべて **日本国内のサーバー（Google Cloud 東京リージョン）** に保管
- 管理者以外はデータにアクセスできないよう **権限管理** を設定
- QRコードの中には個人情報を直接含めず、**ランダムなIDのみ** を使用
- 来場履歴の蓄積は参加者の **同意を得た場合のみ** 記録
- **個人情報保護法** に準拠した運用を行います

---

## 9. 長期運用について

本システムは毎年のオープンキャンパスで継続的に使用されることを想定しています。
チームメンバーの卒業後は、後継学生チームへの引き継ぎ・工学部OC改善委員会への移管・大学への寄贈などを検討します。いずれの場合も運用マニュアルを整備した上で移管します。
